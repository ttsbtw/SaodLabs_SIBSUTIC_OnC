# Лабораторная работа № 1: красно-чёрное дерево

Решение на **Си (C11)** по `lab1___rbtree.pdf`, СибГУТИ.

## Сборка и запуск

В терминале перейдите в папку решения:

```sh
cd /Users/ttsbtw/Desktop/saod/saod_lab1
make
./demo
make experiment
```

Нужны компилятор C (Clang или GCC) и make. Проверено на macOS 26.6.2, ARM64, Apple Clang 21.0.0. Эксперимент использует POSIX `clock_gettime(CLOCK_MONOTONIC)`; на Linux команды те же. На Windows можно использовать WSL.

- `demo` показывает дерево после каждой вставки и удаления, поиск, минимум, максимум и обновление значения.
- `bench` выполняет эксперименты; `make experiment` записывает две таблицы в `results.md`.

Сборка демонстрации без make:

```sh
cc -std=c11 -O2 -Wall -Wextra -Wpedantic demo.c rbtree.c -o demo
./demo
```

## Использование библиотеки

```c
#include "rbtree.h"

int main(void) {
    struct rbtree *root = NULL;
    root = rbtree_add(root, 42, "answer");
    struct rbtree *node = rbtree_lookup(root, 42);
    if (node) rbtree_print_dfs(root, 0);
    root = rbtree_delete(root, 42);
    rbtree_free(root);
    return 0;
}
```

После вставки и удаления сохраняйте возвращённый корень: при повороте он может измениться. Пустое дерево и отсутствующий результат поиска представлены `NULL`. Ключи — `uint32_t`, как требует экспериментальная часть задания (в исходных прототипах встречается `int`). Повторная вставка ключа заменяет значение без создания нового узла. Строка копируется: исходный буфер можно менять или освобождать. Значение `NULL` заменяется пустой строкой. Удаление освобождает узел и его строку; `rbtree_free` освобождает всё дерево. При нехватке памяти программа выводит сообщение и завершается.

При печати `R` означает красный, `B` — чёрный. Дерево показано боком: правое поддерево выше узла, левое ниже; отступ соответствует глубине.

В эксперименте обычное BST хранит только ключи, необходимые для измеряемых операций. Для возрастающих ключей подготовка BST использует указатель на текущий максимум: получается та же правая цепочка, что и при обычных вставках, но без квадратичного времени подготовки. Измеряемые `bstree_lookup` и `bstree_max` всегда проходят дерево от корня. Подробности и ограничения измерений приведены в отчёте.
